## 2. 部署步骤（约 20 分钟）

```
1. 微信开发者工具导入项目根目录
2. 开通云开发 → 新建环境（只有一个环境时无需填 ID；多环境才在 miniprogram/config.js 填 cloudEnv）
3. 依次右键上传并部署全部 10 个云函数（选择「云端安装依赖」）：
   user / profile / memory / simulate / feedback / plan / survey / metrics / notify / visitJob
4. 给 simulate 配置环境变量：LLM_API_KEY、LLM_BASE_URL、LLM_MODEL
   给 visitJob 配置环境变量：SUBSCRIBE_TEMPLATE_ID
5. 云开发控制台 → 数据库 → 新建以下集合（权限统一选「仅管理端可读写」）：
   users, profiles, memoryItems, simulations, actionFeedbacks,
   adjustments, surveyAnswers, metricsEvents, auditLog, pushLogs, subscriptions
6. 云开发控制台 → visitJob → 定时触发器确认已创建（0 0 21 * * * *，每日 21:00）
7. 真机预览，走一遍第 5 节验证清单
```

### 数据库权限说明

所有读写均通过云函数（管理员权限），客户端不直连数据库。因此集合权限统一设为**仅管理端可读写**，避免用户绕过校验直接改数据（例如伪造红线或删除审计日志）。

## 6. 联调常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 云函数报 env 不存在 | 指定了不存在的环境 ID | 清空 miniprogram/config.js 的 cloudEnv 改用默认环境 |
| 推演返回 50001 | LLM_API_KEY 未配置或 BaseURL 错误 | 检查云函数环境变量 |
| 推演返回 50002 | 输出未过校验（红线/概率/结构） | 属预期保护；日志中看 debug 字段原因 |
| 订阅消息不发 | 模板 ID 未配 / 未授权 / 超出订阅额度 | 检查 subscriptions 与 pushLogs 记录 |
| 定时任务不跑 | 触发器未创建 | 云开发控制台手动创建或重新部署 visitJob |
```
