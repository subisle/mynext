# ADR-0001：v1.1 与 v1.0 设计文档的合并裁决

- 状态：已接受（Accepted）
- 日期：2026-10-13
- 决策人：项目负责人
- 背景：仓库内存在两份设计文档——`人生导演台-设计文档.md`（v1.0，含 1.1~1.12 的工程细节）与 `MyNext-设计文档-v1.1-人生模拟与性格评估.md`（v1.1，合规与测量学更严谨）。两者在若干处冲突，需明确以谁为准，避免开发时按两份文档各写一半。

## 裁决总则

**v1.1 为主文档（source of truth），v1.0 降级为工程细节补充。** 冲突处以 v1.1 为准；v1.0 独有且不冲突的内容继续有效。

## 逐项裁决

### 冲突 1：资料采集节奏

| | v1.0 | v1.1 |
|---|---|---|
| 主张 | 信息优先、不设时限；未达基础线（基本+职业+目标）时推演按钮置灰 | 最低限度信息即可开始体验，之后按需补充 |

**裁决：质量分级，不做门槛拦截。**

```
轻推演（最小背景 + 1 个人生主题）→ 立即可用，输出单主题 2-3 条情景路径 + 7 天行动实验
深度推演（完整档案 + 性格测评 + 现实约束）→ 解锁多分支对比、条件/代价/风险完整结构、地域信息注入
缺信息时必须显式提示"当前信息完整度 X%"与"主要不确定因素"，不得用看似确定的细节补全
```

理由：用户明确要求“先获取信息、不考虑时间、支持简洁”，但零信息进入必然产出垃圾推演；用质量分级同时满足体验与质量。

### 冲突 2：长期记忆层（Mem0）的接入时机与地位

| | v1.0 | v1.1 |
|---|---|---|
| 主张 | 现阶段固定采用 Mem0，替代自研 memoryNotes | 阶段 2 再评估接入；记忆服务不得成为唯一事实来源 |

**裁决：采纳 v1.1 的架构原则 + 保留 Mem0 选型。**

```
1. 业务数据库（云数据库）= 唯一事实来源：档案、目标、行动、测评版本与结果、生活事件
2. Mem0 = 仅语义记忆层（偏好、过往解释、长期担忧、对话背景），可随时重建
3. MVP 接入方式：Mem0 Library 或 Cloud API 轻量接入；若赛程紧张可延后，但数据流与删除链路必须预留
4. 删除链路必须覆盖：业务库记录 → 关联摘要 → 向量记录 → 派生数据，并明确告知不可立即删除的备份/法定保留范围
```

### 冲突 3：时间跨度与不确定性

**裁决：采纳 v1.1 的“时间越远、结论越谨慎”，并直接采用其第 4 节分级表作为输出标准。**

v1.0 的 1/3/5/10 年分支树保留为**渲染形态**，但内容标准按 v1.1：7 天=可执行；1 年=可拆阶段；3 年=关键分叉与条件；5 年=情景地图；10 年=宽泛方向与驱动因素，禁止伪精确的收入/职位预测。

### 冲突 4：AI 与用户的目标边界

两者一致（目标只能由用户设定，AI 不代设、不评判、不羞辱）。**裁决：措辞以 v1.1 为准**，v1.0 的话术红线表（禁用“你本应该…”，改用“你给自己定的…”）作为其执行细则保留。

### 新增模块：性格与自我理解评估

**裁决：采纳为正式模块，但严格执行 v1.1 第 10 节“上线前检查清单”。**

```
阶段 0（参赛原型）：只放少量"自我反思问卷"问题，界面与材料均标注"探索性"，不得宣称标准化人格测试
阶段 1：完成 BFI-2 中文版的版本/适用人群/授权/商业使用核查后，才上线正式量表与维度报告
硬约束：AI 不得改写题目、改权重、重算分数；无常模不显示百分位/全国排名；单一人格分数不得排除任何人生路径
```

### 新增内容（全部采纳）

| v1.1 章节 | 用途 |
|---|---|
| 第 4 节 时间跨度与不确定性分级 | 推演输出标准 |
| 第 8 节 分阶段路线（阶段 0~4） | 项目里程碑，取代 v1.0 的 5 天/Phase 表 |
| 第 9 节 验证指标 | MVP 验收标准（不看输出是否流畅，看用户是否执行、是否回来反馈、纠正是否生效） |
| 第 10 节 性格测评检查清单 | 上线门禁 |

### v1.0 独有且继续有效的内容

1. 全字段**备注系统**（备注进入推演上下文并被 AI 引用）
2. 三种采集模式：详细 / 简洁（自然语言一句话）/ 语音访谈式
3. **现实约束引擎**细节（行动标注依据、连续低完成率触发降载、现实突变可冻结目标周期）
4. **每日回访 + 中间回访**（30 秒快答、用户随时发起对话、事件触发回访）
5. 地域社会信息注入（城市级，可选授权，显示来源与更新时间）
6. 单用户闭环创新点表述（Generative Agents 记忆流/规划/反思 → 服务一个真实用户）
7. 参赛口径与材料清单、云开发架构与云函数划分

## 后果

- 开发按 v1.1 的产品与合规标准 + v1.0 的工程实现细节执行。
- 任何后续分歧，一律以本 ADR 的裁决顺序为准：v1.1 产品/合规标准 > v1.0 工程细节 > 其他。
- 若未来 Mem0 或性格测评的合规条件变化，新增 ADR 修订，不直接改本文件。
