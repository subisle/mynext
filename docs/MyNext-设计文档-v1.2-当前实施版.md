## 3. 产品设计要点

### 3.1 画像（信息优先，无时间压力）

- 三组必填字段（基础/教育职业/目标），**每字段带备注**，备注注入推演上下文并以『』引用
- 敏感拦截：身份证/手机号前后端两处拦截（profile 云函数 + profile 页面正则）
- 完整度 = 三组中有值组数 / 3，首页显示并控制推演入口
- 简洁输入哲学：示例引导一句话填写（如"二本计算机 2017，前端，加班多"）
- 目标区含**红线字段**（"不想做的事"）→ 推演硬排除

### 3.2 推演（单主题，七要素）

每次推演：用户给 1 个主题 → AI 结合画像生成 2-3 条路径，每条路径含：

```
title(标题) / narrative(未来1年内阶段变化，可能性非保证) / preconditions(成立条件) /
keyVariables(关键变量) / tradeoffs(机会与代价) / risks(风险与预警) /
uncertainties(不确定性说明，含信息缺口) / weekAction(7天可验证行动，附时间成本)
```

输出标准（v1.1 第 4 节）：7 天=可执行；1 年=可拆阶段；不输出更远时间的具体断言。

### 3.3 反馈与回访

- 行动反馈三态：做完了 / 做了一部分 / 没顾上（+可选原因），入库 actionFeedbacks
- 话术纪律：永远"你给自己定的…"，禁用"你本应该…"；未完成触发降载不说教
- 每日回访（待实现）：定时触发器扫描到期行动 → 订阅消息推送 → 静默期与去重

## 4. 技术架构（当前实现）

```
miniprogram/  原生+TS风格   pages: index(完整度导航) profile(三组画像+备注) simulate(主题→路径卡片→反馈按钮)
cloudfunctions/
  user/       登录：openid 建档/更新登录时间
  profile/    画像 get/save + 敏感拦截 + completeness 计算
  simulate/   推演主流程：取画像→msgSecCheck→LLM→validateOutput→留档→返回
    engine.js 独立模块：SYSTEM_PROMPT + buildUserPrompt + validateOutput（金样例测试对象）
  feedback/   行动反馈入库（三态白名单校验）
tests/golden/ 金样例回归（node tests/golden/golden.test.js，CONSTRAINTS#7 门禁）
```

### 4.1 数据集合

| 集合 | 关键字段 | 说明 |
|---|---|---|
| users | openid, createdAt, lastLoginAt | 用户 |
| profiles | openid, basic/career/goals, confirmedByUser, completeness, updatedAt | 唯一事实来源 |
| simulations | openid, topic, profileSnapshot, promptVersion, model, branches, createdAt | 可解释性留档 |
| actionFeedbacks | openid, topic, branchTitle, weekAction, status, note, createdAt | 反馈流水 |
| （预留）memoryPort | — | 阶段 2 Mem0 接入点；业务库仍为事实来源 |

### 4.2 推演引擎三层防线

```
L1 系统提示词 9 条硬约束：只输出JSON/禁伪精确概率/禁投资标的/禁违法灰色路径/
  禁医疗法律结论/红线硬排除/时间纪律(7天+1年)/信息不足列缺口/备注『』引用
L2 validateOutput：JSON结构校验(七要素缺一即失败) + 红线正则扫描
  (成功率% / SH\d{6},SZ\d{6},BTC,ETH / 刷单,代考,洗钱,逃税,赌博,外挂)
L3 金样例回归 7 断言：合法放行 + 伪概率/股票/违法/路径数拦截 + 红线注入与备注注入快照
  → 任何 prompt/engine 变更必跑，红则禁止部署（CONSTRAINTS#7）
```

模型调用：LLM_API_KEY / LLM_BASE_URL / LLM_MODEL 全部云函数环境变量；原生 https 直连 OpenAI 兼容协议（response_format: json_object），无第三方 SDK 依赖。

### 4.3 可解释性（v1.1 §6.2）

每次推演存画像快照 + promptVersion（当前 v1.1-adr0002-1）+ model + 用户反馈。历史结论与当前结论不同时可溯源；模型升级造成结论漂移可检测。

## 5. 合规红线（CONSTRAINTS.md 摘要）

1 内容安全双闸缺一不可 2 AI 输出强制 JSON 七要素 3 敏感信息两处拦截 4 话术纪律（自设目标）5 无伪精确 6 密钥只进服务端 7 prompt 变更必跑金样例 8 AI 生成内容带标识+免责声明 9 用户自决（查看/更正/删除，删除覆盖派生数据）10 埋点最小集（首次推演完成率/7日反馈回流率/画像纠正比例）
