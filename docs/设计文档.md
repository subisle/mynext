# 评个价 · 微信小程序设计文档

> 版本：v2.0 ｜ 日期：2026-10-12 ｜ 状态：评审稿
> 读者：开发、产品、测试
>
> **v2.0 变更说明**
> 1. 自建爬虫方案整体下线，改为**对接各平台官方 API（开放平台 / 联盟 API）**。
> 2. 评价来源以 **UGC（用户晒单评价）** 为主：发评价必须携带**订单截图 + 订单号**，经校验后获得"已验证"标识。
> 3. 评价对象从"商品"扩展为"万物"（数码、美妆、餐饮、影视、球鞋……），社区玩法**对标虎扑评分**。
> 4. 部署方案评估"要不要服务器"：MVP 推荐**微信云开发（Serverless）**，免运维。

## 1. 项目概述

### 1.1 一句话定位

**"带订单凭证的真实评价社区 + 历史价格工具，万物皆可评。"**

### 1.2 解决什么问题

| 痛点 | 现状 | 本产品 |
|------|------|--------|
| 刷单好评泛滥 | 电商平台评价真假难辨 | 评价必须绑定**订单号 + 订单截图**，未验证的一律打标 |
| 评价分散 | 同一商品散落在各平台 | 按商品聚合多平台评价 + 各平台官方价格 |
| 先涨后降 | 大促前偷偷涨价 | 对接联盟 API 记录历史价格，走势图一目了然 |
| 想等降价 | 天天手动查价 | 关注商品，降价微信订阅消息推送 |
| 只能评商品 | 传统电商评价只覆盖实物商品 | **万物皆可评**：餐厅、电影、App、球鞋、景点…… |

### 1.3 对标虎扑评分的社区设计

虎扑评分的核心是"1~10 分制 + 犀利短评 + 高赞神评"。本产品借鉴：

- **1~10 分打分制**（而非五星制），降低打分心智负担，社区氛围更直接。
- 评价卡片流（短视频化的短评 + 图），**高赞置顶**。
- 商品/事物聚合页展示**大众评分**（类似虎扑的"网友评分"），订单验证评价单独加权。
- 一物一评一投票：可发起"这个东西值不值"式投票话题。

差异化：虎扑评分无交易凭证、无价格维度；本产品用**订单凭证**保证"买过才说话"，用**历史价格**保证"买贵了能看见"。

## 4. 服务器方案评估：要不要传统服务器？

**结论：MVP 阶段不需要传统云服务器，直接用微信云开发（CloudBase / Serverless）；日活过万或出现明确瓶颈再迁移 CVM。**

| 维度 | 微信云开发（推荐起步） | 传统云服务器（CVM + 自建） |
|------|----------------------|--------------------------|
| 运维 | 零运维，无需买机器、配 Nginx | 需自建部署、监控、安全加固 |
| 登录态 | 天然集成 openid，免鉴权开发 | 需自己实现 code2session 与会话 |
| 数据库/存储 | 云数据库 + 云存储开箱即用 | 自购 MySQL/OSS |
| 计费 | 按量付费，前期每月几十元 | 一台 2C4G 约 ¥100+/月，另加数据库带宽 |
| 定时任务 | 定时触发器（拉价格够用） | crontab / xxl-job，更灵活 |
| 弹性 | 自动扩缩容 | 需自己扩容 |
| 局限 | 云函数有并发/时长限制；不能挂长期爬虫；无独立出口 IP | 无明显局限，但全要自己搞 |

**判断依据**：本方案已放弃自建爬虫（官方 API 都是 HTTPS 拉取，云函数完全胜任），数据量级 MVP 阶段云数据库可承载。**云函数 + 定时触发器 + 云数据库 + 云存储**四件套覆盖全部需求。

**预留迁移路径**：业务层全部走"云函数 = HTTP 接口"的写法，将来换 NestJS/Go 平滑迁移，前端只改 baseURL。

## 6. 官方 API 对接设计

### 6.1 现实约束（必读）

> 官方开放平台**普遍不开放"评价"类数据接口**——评价是平台核心资产。开放的主要是**商品 / 价格 / 优惠券**查询（多面向 CPS 推广场景）。因此本方案的数据分工是：
>
> - **价格、商品信息** → 官方联盟 API（合规、稳定）。
> - **评价内容** → 用户 UGC 晒单（订单号 + 截图验证），这正是产品核心价值所在。

### 6.2 各平台官方 API 对接表

| 平台 | 官方入口 | 可获取 | 申请条件 | 限制 |
|------|---------|--------|---------|------|
| 京东 | 京东联盟开放平台 union.jd.com | 商品详情、实时价格、券 | 个人/企业可注册，需创建推广位 | QPS 有限制，价格接口为主 |
| 淘宝/天猫 | 淘宝联盟 open.taobao.com（阿里妈妈） | 商品详情、价格、券 | 需实名，部分接口要企业资质 | item 评价接口已不对个人开放 |
| 拼多多 | 多多进宝 open.pinduoduo.com | 商品详情、价格、券 | 企业入驻为主 | 审核较严 |
| 苏宁 | 苏宁开放平台 | 商品、价格 | 企业资质 | 类目较窄 |
| 微信 | 小程序订阅消息、内容安全 API | 推送、文本/图片审核 | 小程序认证 | 免费额度充足 |

### 6.3 对接规范

~~~text
1. 统一 Adapter 层：JdAdapter / TaobaoAdapter / PddAdapter
   - searchItem(keyword)
   - getItemDetail(platformSkuId)
   - getPrice(platformSkuId)
   - parseLink(url) -> platformSkuId
2. 签名与凭证：appKey/secret 存云函数环境变量，绝不放前端
3. 限流：每平台本地令牌桶 + 云函数内存计数，超限排队
4. 失败降级：单平台 API 故障时该平台价格显示"暂无报价"，不影响其他平台
5. 数据缓存：商品详情缓存 1 小时，价格缓存 10 分钟（云数据库 price_cache 集合）
~~~

## 7. 核心设计：晒单认证（订单号 + 订单截图）

### 7.1 流程

~~~mermaid
flowchart LR
    A[用户发评价] --> B{是否晒单认证}
    B -- 否 --> C[发布<br>标记：未验证]
    B -- 是 --> D[填写订单号<br>+ 上传订单截图]
    D --> E{格式校验}
    E -- 不通过 --> D
    E -- 通过 --> F[截图审核<br>机审: OCR + 内容安全API]
    F -- 存疑 --> G[人工抽审队列]
    F -- 通过 --> H[发布<br>标记：已验证徽章]
    G -- 通过 --> H
    G -- 驳回 --> D
~~~

### 7.2 订单号校验规则

| 平台 | 校验规则（示例，按实测调整） |
|------|---------------------------|
| 京东 | 10~14 位纯数字 |
| 淘宝/天猫 | 17~19 位纯数字 |
| 拼多多 | 18~20 位纯数字 |

校验只做**格式合法性**（长度 + 数字），不做平台真伪查询（官方无此接口）。真伪由"截图审核 + 社区举报"兜底：

- 机审：云函数调用微信**内容安全 API**（图片 security.imgSecCheck）+ OCR（腾讯云 OCR）提取截图中的订单号，与用户填写比对一致才通过。
- 抽审：新用户前 3 条认证评价 100% 人工复核；老用户按 10% 抽审。
- 举报：被举报 ≥ 5 次进入人工复审，伪造凭证拉黑并撤销其历史"已验证"徽章。

### 7.3 隐私保护（合规重点）

1. 上传引导页**强制提示**：遮挡收货人姓名、电话、地址（提供示例图）。
2. 订单号存储脱敏：展示时只显示前 4 位 + **** + 后 2 位。
3. 截图存云存储**私有读**，仅通过临时 URL（有效期 30 分钟）在评价详情展示。
4. 用户可随时删除自己的评价，删除即物理删除截图文件。

### 7.4 评分与权重

~~~text
事物总分 = 已验证评价均分 × 0.7 + 未验证评价均分 × 0.3   （评价数 ≥ 5 时展示大众评分）
排序权重 = 验证标识 > 点赞数 > 时间
~~~

## 8. 数据模型（云数据库集合设计）

| 集合 | 关键字段 | 说明 |
|------|---------|------|
| users | openid, nickname, avatar, credit(信用分), createdAt | 信用分用于审核放行策略 |
| things | title, category, brand, images, tags[], platforms[], avgScore, verifiedScore, reviewCount, hot | 万物统一实体：商品/电影/餐厅共用 |
| platformItems | thingId, platform, platformSkuId, url, currentPrice, updatedAt | 一物多平台映射 |
| reviews | thingId, userId, score(1~10), content, images[], orderNo(脱敏存), orderImgFileId, verified(bool), verifyStatus, likeCount, status | 核心集合 |
| priceRecords | thingId, platform, price, captureTime | 定时任务每日写入 |
| follows | userId, thingId, targetPrice, notifyNewReview, createdAt | 关注与提醒条件 |
| pushTasks | userId, thingId, type(priceDrop/newReview), status, sentAt | 推送记录（幂等去重） |
| reports | targetType, targetId, reason, status | 举报队列 |

索引要点：reviews(thingId, verified, likeCount)、things(title 分词索引)、follows(userId)、priceRecords(thingId, platform, captureTime)。

## 9. 接口设计（云函数）

统一约定：小程序端调用 wx.cloud.callFunction；返回 code/msg/data 三段式。

| 编号 | 云函数 | 动作 | 说明 | 登录 |
|------|--------|------|------|------|
| API-01 | user | login | 静默登录 | 否 |
| API-02 | search | keyword | 关键词搜索 | 否 |
| API-03 | search | parseLink | 解析平台链接，返回或创建 thing | 否 |
| API-04 | thing | detail | 详情：聚合评分 + 各平台现价 + 价格摘要 | 否 |
| API-05 | review | list | 评价流（游标分页，可筛选已验证） | 否 |
| API-06 | review | create | 发评价（含订单凭证） | 是 |
| API-07 | review | like / report | 点赞 / 举报 | 是 |
| API-08 | thing | createThing | 万物自由创建（审核后可见） | 是 |
| API-09 | follow | add / remove / list | 关注管理 | 是 |
| API-10 | price | history | 价格走势（30/90/365 天） | 否 |

API-04 返回示例：

~~~json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "thingId": "t_9123",
    "title": "XX 降噪耳机 4 代",
    "avgScore": 7.8,
    "verifiedAvgScore": 8.1,
    "reviewCount": 342,
    "verifiedCount": 121,
    "platforms": [
      { "platform": "jd", "price": 199.00, "lowest": 159.00, "url": "https://item.jd.com/..." },
      { "platform": "taobao", "price": 189.00, "lowest": 179.00 }
    ]
  }
}
~~~

## 10. 页面设计

| 页面 | 路由 | 核心内容 |
|------|------|---------|
| 首页 | pages/index | 搜索框 + 粘贴链接入口 + 热门评分榜 + 值不值话题流 |
| 搜索结果 | pages/search | 事物列表（评分 + 最低价 + 评价数） |
| 事物详情 | pages/thing | 大众评分（虎扑式 1~10）· 价格走势图 · 评价流（全部/已验证/有图）· 关注按钮 |
| 发评价 | pages/review/edit | 打分 1~10 + 短评 + 图 + 晒单认证入口（订单号 + 截图上传） |
| 关注页 | pages/follow | 关注列表（现价、降价角标）、订阅消息授权引导 |
| 我的 | pages/user | 我的评价、我的认证徽章、消息、设置 |

关键交互：用户点"关注"时同时调用 **wx.requestSubscribeMessage** 申请一次性订阅额度；额度耗尽前在关注页提前再次申请（引导勾选"总是保持以上选择"）。

## 11. 价格与推送逻辑

~~~text
priceJob（定时触发器，每 2 小时）：
1. 遍历"活跃 thing"（近 7 天有浏览/关注/评价）× platformItems
2. 调官方联盟 API 取现价，写 priceRecords，更新 platformItems.currentPrice
3. 匹配降价规则：
   - 现价 <= follows.targetPrice
   - 现价 <= 历史最低价（priceRecords 聚合）
4. 同一用户同一 thing 每天最多 1 条（pushTasks 去重），投递 pushTasks

pushJob（每 10 分钟）：
1. 取 status=待发的 pushTasks（过滤 00:00~07:00 静默期，顺延）
2. 调 subscribeMessage.send 发送，回写状态与 msgId
3. 失败指数退避重试 3 次
~~~

推送模板（降价提醒）示例字段：商品名称、当前价、关注时价格、"降价啦，快去看看"。

## 12. 内容安全与合规

| 事项 | 措施 |
|------|------|
| UGC 文本/图片审核 | 发布前强制过微信内容安全 API（msgSecCheck / imgSecCheck），机审不过不发 |
| 小程序类目 | 需开通"电商/工具"相关类目；UGC 社区类目注意资质要求，提前查最新《小程序类目表》 |
| 电商类目资质 | 若展示价格并引导跳转平台，走 CPS（联盟）合规路径，不算自营交易，无需 ICP 电商资质 |
| 个人信息 | 不收集手机号；订单信息脱敏、私有存储、可删除（符合《个人信息保护法》最小必要原则） |
| API 合规 | 仅使用官方开放/联盟 API，不破解签名、不伪造登录态 |
| 评价真实性 | 验证徽章体系 + 举报复审 + 伪造拉黑，防止"晒单认证"被滥用 |

## 14. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 联盟 API 申请被拒（个人主体） | 高 | MVP 先只接京东联盟（个人可申请）；主体建议注册个体工商户/公司提资质 |
| 晒单凭证伪造 | 高 | OCR 比对 + 抽审 + 举报复审 + 信用分体系 |
| 订阅消息额度不足（一次订阅一发） | 中 | 关注页高频引导"总是保持"；站内消息中心兜底 |
| 联盟 API 限流/接口变动 | 中 | Adapter 隔离 + 降级显示"暂无报价" + 版本跟随官方公告 |
| UGC 内容合规 | 中 | 先审后发（机审）+ 人工队列 + 举报机制 |
| 云开发量级瓶颈 | 低 | 业务层按 HTTP 风格封装云函数，预留迁 CVM 路径 |
